# Proyecto: Transcriptor local de audio con Faster-Whisper aislado mediante Docker

Quiero que desarrolles un proyecto pequeño, autocontenido, reproducible y seguro para realizar transcripciones locales de archivos de audio utilizando **Faster-Whisper** dentro de Docker.

El proyecto será utilizado inicialmente para un caso aislado, pero debe quedar correctamente diseñado y documentado para poder reutilizarse posteriormente sin modificar el sistema operativo host.

## 1. Contexto del entorno

El host es:

* Fedora 44.
* Docker ya se encuentra instalado y funcionando.
* El host se mantiene deliberadamente limpio.
* Python del host NO debe utilizarse para ejecutar Faster-Whisper.
* No deben instalarse paquetes RPM, Python, FFmpeg, CUDA, pip, bibliotecas ni dependencias adicionales en Fedora.
* Todos los componentes necesarios para la transcripción deben permanecer encapsulados dentro de Docker o dentro del directorio controlado del proyecto.
* No se utilizará GPU inicialmente.
* La ejecución debe realizarse mediante CPU.
* Arquitectura esperada: `x86_64`.

Python instalado actualmente en el host:

```text
Python 3.14.6
```

Este Python **no debe modificarse, reemplazarse ni utilizarse como dependencia del proyecto**.

---

# 2. Objetivo

Construir una herramienta CLI basada en:

* Docker
* Docker Compose
* Python 3.12 dentro del contenedor
* Faster-Whisper
* modelo Whisper `large-v3`

que permita ejecutar algo conceptualmente equivalente a:

```bash
./transcribir.sh ./audios/audio.mp3
```

y obtenga como salida una transcripción fiel al audio.

Ejemplo:

```text
./resultados/audio.txt
```

Opcionalmente también deberá poder producir:

```text
./resultados/audio.srt
./resultados/audio.vtt
```

La aplicación NO es un servidor web.

NO requiere HTTP.

NO requiere API.

NO requiere base de datos.

NO requiere ningún puerto TCP o UDP.

Su arquitectura debe permanecer deliberadamente simple.

---

# 3. Principio fundamental: proteger el host

El proyecto debe aplicar el principio:

> Todo lo necesario para Faster-Whisper pertenece al contenedor; Fedora solamente proporciona Docker.

Está explícitamente prohibido que el proceso de instalación ejecute comandos como:

```bash
sudo dnf install ...
pip install ...
pip3 install ...
python -m pip install ...
```

sobre el host.

También está prohibido:

* modificar `/usr`
* modificar `/usr/local`
* modificar `/etc`
* modificar `$HOME/.local`
* modificar el Python del sistema
* modificar configuraciones de shell
* instalar FFmpeg en Fedora
* instalar CUDA en Fedora
* instalar CTranslate2 en Fedora
* crear virtualenvs Python en Fedora
* crear servicios systemd
* modificar firewall
* modificar SELinux
* desactivar SELinux
* agregar repositorios RPM
* modificar Docker daemon
* abrir puertos

Si alguna dependencia es requerida, debe instalarse exclusivamente dentro de la imagen Docker.

# 4. Seguridad de red

Este requisito es obligatorio.

## 4.1 No publicar puertos

El proyecto NO puede utilizar:

```yaml
ports:
```

bajo ninguna circunstancia.

Tampoco debe utilizar:

```text
-p
--publish
-P
--publish-all
```

en ningún script.

No quiero puertos expuestos como:

```text
0.0.0.0:XXXX
127.0.0.1:XXXX
[::]:XXXX
```

Ni siquiera se debe publicar un puerto únicamente en localhost.

La aplicación no necesita escuchar conexiones entrantes.

## 4.2 `EXPOSE`

No agregar instrucciones:

```dockerfile
EXPOSE
```

al Dockerfile salvo que exista una justificación técnica real, que en principio no existe para este proyecto.

## 4.3 Red durante ejecución

Analiza cuidadosamente el ciclo de vida del modelo.

Faster-Whisper puede necesitar acceso a Internet para obtener inicialmente el modelo.

Diseña una estrategia donde:

1. la descarga inicial del modelo esté controlada;
2. el modelo quede persistido únicamente dentro de una carpeta del proyecto o volumen específicamente definido;
3. una vez disponible el modelo, la transcripción normal pueda realizarse sin necesidad de Internet cuando técnicamente sea posible.

Evalúa si resulta apropiado ejecutar la fase de transcripción con:

```yaml
network_mode: none
```

o su equivalente.

NO lo apliques ciegamente si impediría el funcionamiento inicial.

Documenta claramente:

* cuándo necesita red;
* por qué;
* cuándo deja de necesitarla;
* cómo verificar que el procesamiento habitual funciona sin red.

La arquitectura preferida es:

```text
Internet
   │
   │ solo cuando sea necesario descargar dependencias/modelo
   ▼
Docker
   │
   ├── Faster-Whisper
   ├── CTranslate2
   ├── PyAV
   └── modelo large-v3

Transcripción normal
   │
   X Internet
   X puertos
   X servidor
```

```bash

    --model large-v3 \
    --format txt
```

Debe utilizar:

```python
device="cpu"

```

como configuración inicial.

Debe utilizar idioma español:

No reinterpretar.
